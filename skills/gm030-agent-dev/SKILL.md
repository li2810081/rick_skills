# gm030 多 Agent 开发编排

用户只与 Hermes 交互。分工：**Codex 出蓝图与里程碑，ZCode 承担主要编码量（有量价优势），Hermes 做调度、验收、返工与推进。** 本技能只定义跨 Agent 编排规则；工程质量门禁复用 `rick-dev`，CLI 调用与会话绑定复用 `agent-dispatch`，冲突处理复用 `merge-reconciler`。不复制测试规范、CLI 手册、角色体系；不建 Bot/Profile/看板平台/默认 cron。

## 七步循环

1. **恢复实况**：读项目约定（AGENTS.md）、git 状态、现有蓝图和执行记录；先核对有无未结束任务。项目记录只是索引，代码与进程状态是核对依据，冲突时先纠正记录，不拿过期文档重新初始化已有项目。
2. **补足方案**：蓝图不足才交 Codex 只读设计（-s read-only），产出范围、依赖、里程碑、验收条件、未知项。已有合格蓝图沿用，不重复设计。
3. **用户确认**：关键方案、取舍和授权范围由用户定。确认后，授权范围内的实现、测试、返工、下一里程碑由 Hermes 推进，不逐项问。授权不被看板卡或子 Agent 提示词扩大。
4. **派发 ZCode**：一次一个可验收里程碑。显式传 --cwd 和权限模式；**headless 默认是 yolo，必须显式指定更严模式，禁止为绕过审批自行切 yolo**。启动前登记运行编号与起始 commit；启动后补会话 ID（未返回记"待绑定"）。同一目录同一时刻只允许一个写入执行者（含其子进程）。
5. **核对结束**：完成事件或超时后，核实进程、会话和工作区才进下一步。**超时只代表观察结束，不代表任务停止**；未确认实现进程退出前，禁止新写入者进入，也禁止 Hermes 自动接手改码。状态不明标"运行待核实"并暂停。
6. **验收与返工**：Hermes 回读 diff、逐条验收证据、按 rick-dev 跑测试与冒烟。里程碑通过只能由 Hermes 判定——ZCode 的完成声明、退出码、单测全绿都不单独算数。实现问题退 ZCode（带具体失败证据和允许范围，不重发整套背景）；设计问题交 Codex；需要用户决策才上报。同一失败重复出现且无新证据时停止循环上报，不许删测试或放宽验收换通过。主观效果验收停"待用户评价"。
7. **记录并推进**：保存验收结论和下一步到项目内执行记录（复用已有蓝图/里程碑文件，缺了才加一个短文件）。上一运行已结束、验收通过、依赖满足、仍在授权内，才派下一项。完成通知只触发核查，不直接触发下一轮实现。

## 执行记录最小字段

项目绝对路径与仓库身份/分支；里程碑 ID 与验收条件；已授权动作及来源；运行编号、Agent、准确会话 ID、进程标识、起止时间；起始 commit；当前状态（运行中/等待审批/待验收/返工/通过）；变更摘要与验证证据；未解决问题与下一步。派发前、启动后、结束或挂起时、验收后更新。记录要足以让新 Hermes 会话接手，不依赖旧会话记忆。

## 并行（可选）

独立任务可并行：每个执行者一个分支 + **独立 git worktree**（同目录多分支会互踩）。前提是 Codex 蓝图已定公共契约、文件责任不重叠；共享热点指定单一负责人。数据库、生成文件、日志、端口须隔离。集成串行：各分支通过≠合起来通过，合入后重跑相关测试与跨模块冒烟。冲突不许直接 ours/theirs：简单冲突按双方意图处理，设计冲突交 Codex。分支与集成操作须在事先授权内。起步限两个并行执行者。

## 边界与禁止宣称

- 提交/推送/合并主干/部署/删真实数据/动凭证，仅凭用户明确授权。
- 审批挂起：区分"等待工具审批/等待用户决策"，记录后暂停，不当普通失败重试。
- 不宣称：Skill 提供持久后台调度、应用关闭后持续运行、模式名等于安全保证、超时=停止、通知=验收通过、单测全绿=目标完成、任何未测量的节省比例。
- 降上下文成本：蓝图留在项目里交路径和段落；返工只交失败证据；Codex 只审争议点不重审全仓；会话核对无误可续用。
- 新会话按记录恢复，不凭"最近会话"或相似任务名续接。
