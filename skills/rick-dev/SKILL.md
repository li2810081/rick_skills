# rick-dev —— 让个人项目保持"轻松开发"的流程

**分工（重要）**

| 放在哪 | 放什么 | 为什么 |
|---|---|---|
| 本 skill | 通用流程：闸门、循环、停手条件、发布仪式、边界、验收清单 | 跨项目完全相同，改一次全体受益 |
| 项目仓库 | 项目事实：命令、部署目标、字段语义、踩坑、发布记录 | 必须跟代码走，换机器换人都要能看到 |
| 工具记忆 | 跨项目偏好、用户纠正、工具/环境坑 | 换项目仍适用 |

**先读项目文件再动手**：`AGENTS.md`（或同类）→ `docs/TRAPS.md` → `docs/RELEASE.md`。没有就读 `references/project-facts.md` 走首次接入。

## 为什么这套能让人轻松（三个真正的杠杆）

1. **验证便宜到能自证** —— 一条命令跑完整验证，跑在隔离数据上。做不到就先补这个，而不是先补流程。
2. **领域事实写下来** —— 字段语义、单位、主数据归属、外部系统契约。让 AI 不用猜，返工率立刻下降。
3. **发布可逆且仪式化** —— 备份 + 固定步骤 + 保留旧产物。人敢说"发布"，因为它能退回去。

其余都是这三条的配套。**别把配套当核心。**

## 门槛分层

不是每个改动都要走完整发布仪式。先按影响范围分层：

- **核心必做（所有改动）**：只读探索、最小验证、合适的冒烟检查、`git status` 核对、如实报告结果。
- **L1 增强（公共接口、跨模块、依赖升级、用户可见行为）**：增加一次只读独立复核，并记录未覆盖项。
- **L2 高风险（认证权限、密钥、生产、资金、数据迁移、不可逆写入）**：执行备份、回滚准备、反证检查和发布后健康核对；未知项默认阻断。

本地可逆的小改动不必强行创建 tag、备份生产或演练回滚；只有进入发布或 L2 风险时，才启用完整发布仪式。

## 日常循环

```
① 人说需求 → ② 只读探索 + 出计划（改哪些文件、怎么验收、风险）
→ ③ 人确认计划 → ④ 实现（小步可逆）→ 跑测试闸 → 自查
→ ⑤ 人看效果 → ⑥ 人说"发布" → 执行发布仪式
```

人的动作只有四个：**说需求 / 确认计划 / 看效果 / 说发布**。

**每阶段汇报**：做了什么、耗时、依据（命令/文件/数据）、下一步。

**停手条件（遇到就停，不要静默重试）**
- 同一根因的两次不同处理仍未解决（同一命令重复执行不计为新的尝试）
- 需要生产写权限、需要动外部系统
- 发布中生产不可达 / 服务异常
- 需求边界变了，或计划前提不成立

已在当前会话明确授权的动作无需重复询问；涉及不可逆、资金、权限或高风险数据变更时，仍需单独确认影响和回滚。

**发布中服务不可达协议**：先判断"是发布引起的还是本来就坏" → 停止推进（不动数据、不反复重启）→ 只读取证（状态/日志/端口/健康检查）→ 如实汇报现象与需要谁介入 → 恢复后先复验基线再从断点继续。

## Web UI 重构路由（任务是"重构 / 优化 / 美化 UI"时直接走这里）

按变更管理 Baseline → Change → Compare 展开，两个 skill 一进任务就调用：

1. **Baseline**：动手前先用 `web-design-guidelines` 审计现状，拿 `file:line` 问题清单当重构依据——不凭感觉改，清单就是重构范围。
2. **Change**：视觉翻新（换风格/换气质）先用 `frontend-design` 出 token 系统（色/字/布局/签名元素）和简短设计计划再动手；纯细节修复（可访问性/交互/表单）直接按清单改，不动视觉方向。
3. **Compare**：改完复扫一遍——老问题清零、没引入新问题才算重构成功；有 Baseline 才允许说"变好了"，否则只算"发生了变化"。

## 轻量风险路由（按风险升级，不按习惯加仪式）

先分级，再决定是否需要独立复核；文件数量不是风险的唯一指标。

- **L0**：本地、可逆、小范围、无外部影响。走现有测试闸 + 自查，不额外启动评审。
- **L1**：公共接口、跨模块、依赖升级或可见行为变化。增加一次**只读独立复核**，只找证据支持的问题，不直接改文件。
- **L2**：认证/权限、密钥、安全边界、数据迁移、生产、资金或不可逆操作。增加独立安全/反证检查、关键测试和回滚验证；未知项默认阻断，不用猜测补齐。

独立复核不是固定三路 Agent：同一模型的多份意见不等于独立证据。只在风险达到 L1/L2 时启用，结果必须区分 `confirmed finding`、可能风险和未覆盖项。

## 反自欺证据卡（关键结论或 L1/L2 必填）

```text
结论：
依据：<文件 / 命令 / 数据>
状态：事实 | 假设 | 推断 | 未知
反证：<什么结果会证明我错，如何验证>
验收断言：<可观察的通过条件>
回滚：<怎么撤回，材料在哪里>
```

失败、未知、证据不足只能报告为未完成/阻断，不能包装成“已通过”。涉及生产、权限或数据的未知采用 fail-closed。

## 先理解，再最小化（吸收 ponytail 的低副作用部分）

先读清任务和真实调用链，再按顺序问：

1. 这件事是否需要存在？
2. 项目已有 helper / util / pattern 能否复用？
3. 标准库能否解决？
4. 平台原生能力能否解决？
5. 已安装依赖能否解决？
6. 能否用一行或更小的改动解决？
7. 都不行，才写最小自定义实现。

这是减少过度工程，不是跳过理解。不得因此删掉信任边界校验、错误处理、数据保护、安全、可访问性或用户明确要求。修 bug 前查找被修改函数的所有调用方，优先修共享根因，不只修报告路径。

## 简化债务与最小检查

有意采用有上限的简化时，留下短注释或交付记录：`simplification: <当前取舍>; ceiling: <已知上限>; upgrade: <触发条件/升级路径>`。没有触发条件的“以后再做”视为未登记债务。可用一次 grep 或 `/review` 复核这些标记，避免静默腐烂。

分支、循环、解析器、金额/安全逻辑等非平凡逻辑至少留下一个可失败的最小检查（assert、demo 或小测试）；简单一行不为形式新增测试。

## 可选 beads 账本与复杂度复核

项目已有 `.beads/` 或明确启用 beads 时，才用 `bd ready/create/dep/close` 记录阻塞、依赖、未完成后续事项和跨会话交接点；没有就沿用项目任务文件，不自动初始化。Beads 是未完成事项账本，不是测试通过证明，也不以 bead 数量代替验收。

需要时可做一次只读 `complexity review`：只检查死代码、单实现抽象、重复造轮子、不必要依赖、无触发器配置和可删除层；输出删除/替代建议，不自动修改。正确性、安全、性能问题回到常规检查，不能用“代码更短”冒充“代码正确”。

## 三道闸门（细节见 `references/gates.md`）

1. **测试闸**：有测试或自检时，一条命令全绿，跑在隔离数据上；**把隔离做成断言**（连接目标不在临时库就直接退出）。失败先判断是产品错了还是测试写宽了——不许为过测试而放宽断言。
2. **冒烟闸**：按形态选——Web UI（浏览器真点）/ exe（真启动走主流程）/ API·MCP（真请求验契约）/ 定时任务或脚本（真实触发一次）/ 静态前端（真实访问入口）。铁律：**单测全绿 ≠ 可用**。Web UI / 静态前端另做**设计双检**：视觉方向按 `frontend-design`（反模板化三俗、一个签名元素），交付前用 `web-design-guidelines` 扫执行细节（可访问性/交互/表单/暗色模式等 100+ 条）。
3. **隔离闸**：未明确授权的写入先问；当前会话已明确授权的写操作无需重复询问，但不可逆、资金、权限或高风险数据变更仍要单独确认影响与回滚。生产操作先备份并写回滚；改数据结构属高风险。

## 发布仪式

先读项目里的 `docs/RELEASE.md`；没有就按形态走：

- Docker → `references/release-docker.md`
- exe / 可执行产物 → `references/release-exe.md`
- 定时任务、脚本、静态前端、服务器服务或其他形态 → `references/release-other.md`

公共约定：命名一致（tag / 产物 / 运行时版本）、**从 tag 干净构建**、产物校验和、保留旧版本、**回滚要演练过**（没演练过的回滚是假设）。禁止：覆盖生产配置、删数据、跳过备份。

## 硬边界与如实报告

- 提交只含本轮相关文件；本地数据/缓存/临时产物不提交
- 未提交改动先问归属，不擅自提交、不擅自丢弃
- **不擅自合并主干、打 tag、部署** —— 只有人明确说"发布"才执行
- 不擅自改生产配置与权限；需要时先给「影响 + 回滚」
- 失败就说失败并贴证据；跳过哪步要写出来；**不许把"接口报错"说成"已通过"**
- 涉及数据/权限/外部系统的操作，先给影响与回滚再动手

## 验收清单（发布前逐条打勾）

- [ ] 全量验证在隔离环境通过（记录结果与耗时）
- [ ] 静态/迁移/安全检查通过
- [ ] 冒烟闸按形态走过一遍
- [ ] `git status` 核对：只动了预期文件
- [ ] 产物从 tag 干净构建，不含密钥或本地数据
- [ ] 生产已备份（数据 + 配置 + 旧版本标识），路径已记录
- [ ] 部署后健康检查正常、日志无异常
- [ ] 关键行为在生产抽查过（只读方式）
- [ ] **人确认过效果**（AI 不能自认验收通过）
- [ ] 回滚方式与材料写进交付报告
- [ ] 未完成/存疑项明确列出
