# 三道闸门（细节与写法）

## 闸门一：测试闸

**要求**
- 一条命令跑完整验证；命令里**显式指定**隔离数据位置，不依赖默认连接
- 全绿才算过
- **可自动复现的 bug 必须红-绿**：先编写并运行一个能复现该 bug 的失败测试（无需单独提交失败状态），再修复让它变绿。若问题属于视觉、配置、部署、一次性数据修复，或自动化测试成本明显高于风险，改用可重复的复现脚本、真实请求、截图、日志或数据快照作为证据，并写明为什么不做红-绿测试。
- 失败先判断性质：
  - 产品行为确实变了 → 改测试，并在提交说明里写清行为变更依据
  - 测试选错了对象 / 断言过宽 → 修测试（**不要改产品去迁就测试**）
  - 不许为过测试而放宽或删除断言

**把隔离做成断言（关键）**

"记得要隔离"这种提醒拦不住事故。某项目曾因环境变量名写错（用了 `DJANGO_DB_NAME`，
实际只认 `DJANGO_SQLITE_PATH`），基准脚本把测试数据写进了现有库。正确做法是**跑测试前断言连接目标**：

不要只检查环境变量或临时目录前缀：应用可能忽略变量，路径可能含 `..` 或链接，临时目录内也可能有现存数据。Shell 的 `TMPDIR` 为空时，`"$TMPDIR"/*` 会匹配任意绝对路径，不能作为安全断言。

项目测试引导必须在任何写入、迁移、fixture 加载前执行以下检查：

1. 由测试运行器创建本轮唯一的临时库/目录，记录本轮拥有的资源标识；不复用现存业务库。
2. 加载应用实际使用的配置，再从数据库连接对象读取实际目标；检查所有会写入的连接别名。SQLite 对实际路径做规范化并处理符号链接，与本轮创建的确切文件比较；远程数据库核对 host、port、库名/schema 和专用测试身份。
3. 验证实际目标确实属于本轮隔离资源，且测试身份无生产写权限。不能验证就拒绝运行有副作用的测试。
4. 外部 API、文件、对象存储、队列也使用隔离资源或禁止真实写入的替身；数据库隔离不能证明其他副作用已隔离。
5. 清理只针对本轮创建且核对过归属的资源。

至少验证一次：配置变量被忽略、目标指向现存库或某个连接别名未隔离时，测试必须在首次写入前失败。具体断言以项目连接接口实现，不提供仅靠环境变量判断的通用安全代码。

**判断"是产品错了还是测试写宽了"**
- 断言的是**业务规则**（权限、金额、状态机）→ 大概率产品错了
- 断言的是**实现细节或取样对象**（比如"取第一个属性"结果取到了新属性）→ 大概率测试写得太宽
- 拿不准时：先复现用户能看到的那个现象，用事实判断

## 闸门二：冒烟闸（按形态选）

**A. Web UI**：起本地栈 → 浏览器真点 3~5 条核心路径 → 记录每条的结果
**B. exe / 桌面程序**：构建后**真实启动**一次 → 走主流程 → 确认窗口/菜单/关键操作可用、无报错弹窗、关于页版本号正确
**C. API / MCP**：用真实请求打一次 → 校验返回契约（字段齐、类型对、错误码对、鉴权对）

**铁律**：单元测试全绿 ≠ 可用。历史上出过"测试全过、页面点不动"的事故。

**分工**：视觉、手感、措辞属于**人**。AI 报告「我验证了什么」（DOM 结构、接口返回、数量、状态），
人回答「好不好看、顺不顺手」。主观效果由约定验收人确认；纯客观任务可按约定断言报告技术验收通过，不能替人作主观判断。

**注意**：截图/自动化接口本身可能失败，此时要明确说"视觉验收未完成"，
不能用 DOM 检查冒充视觉通过。

## 闸门三：隔离闸

- **未明确授权的写入先问**：允许对生产/外部系统做只读查询取证；当前会话已经明确授权的写操作无需重复询问，高风险操作先明确影响和恢复方案，只有新增影响或未被现有授权覆盖时才另行确认
- 生产操作前必须**先备份**：数据 + 配置 + 当前版本标识，落到带时间戳的目录并记录路径
- **改数据结构属高风险**（字段类型、单位、含义）：先说清"旧版本还能不能跑新数据"，能不给就等确认
- 外部系统回写（若项目有）：白名单控制、只写人工改过的值（防回环）、失败不阻断本地但必须留日志
- 数据源优先级写死在项目事实里：**谁是主，冲突时以谁为准**

### 写操作前后核对（适用于 L1/L2 或任何外部写入）

**执行前**，用最短记录写清：

- 影响范围：哪些文件、数据、服务或外部对象会变
- dry-run：能做就先做；不能做就明确说明为什么
- 回滚材料：备份、旧产物、down migration 或撤回命令在哪里
- 预期差异：执行后只允许出现哪些变化

**执行后**，先只读核对实际状态，再决定是否继续：

- 实际变化是否只落在预期范围
- 关键健康检查、版本、数量、校验和是否符合预期
- 是否有异常、未完成项或超出副作用预算的变化

预期与实际不一致就停，不用静默重试或继续扩大范围；记录差异，回到证据卡和回滚路径。
