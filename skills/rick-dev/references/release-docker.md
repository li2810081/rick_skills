# 发布仪式 · Docker 路线

> 用前先读项目里的 `docs/RELEASE.md`（已填好的本项目版本）；本文件是骨架与检查点。

## 0. 命名约定
- 版本 tag：`vX.Y.Z`（版本号只升不改）
- 产物：`vX.Y.Z-<短hash>`；镜像/包同名
- **tag、产物名、运行时版本三者必须互相对得上**（短 hash 一致）

## 1. 门禁
- 测试闸全绿（记录数量与耗时）
- 静态/迁移/安全检查通过
- 冒烟闸按形态走过（浏览器 / exe 启动 / 真实请求）

## 2. 提交与标记
- 只提交本轮相关文件（`git status` 逐项确认；本地数据、缓存、临时产物不要提交）
- 未提交的无关改动先问归属，不擅自提交/丢弃
- 合主干 → 打 tag → 推送

## 3. 干净构建
- **从 tag 导出构建**（例如 `git worktree add <tmp> <tag>`），避免把本地未跟踪文件、密钥、测试数据打进产物
- 抽查产物内容：不应含 `.env`、本地数据库、备份文件
- 产物算校验和并记录

## 4. 备份生产（发布前，必须有）
```bash
BD=backups/vX.Y.Z-$(date +%Y%m%dT%H%M%SZ); mkdir -p "$BD"
# 1) 数据
<备份命令> > "$BD/db.sql"        # 校验非空、有结束标记、记录字节数
# 2) 配置
cp docker-compose.yml "$BD/"; cp .env "$BD/env.bak"; chmod 600 "$BD/env.bak"
# 3) 当前版本标识
docker inspect <app容器> --format '{{.Config.Image}}' > "$BD/old-image.txt"
```
记录：备份目录路径、数据大小、旧版本标识。

## 5. 上传与部署
1. 上传产物 → **两端 sha256 比对一致**再继续
2. `docker load`（或等价的导入）
3. 只改配置里**版本相关的行**（不要整体覆盖生产配置）
4. `docker compose up -d` 重启
5. 等健康检查通过（注意：**健康检查可能需要带 Host 头**，否则会被判 400）
6. 核对数据迁移已应用
7. **刷新静态资源**：容器重建后，本地目录挂载可能覆盖镜像内的新资源 —— 核对源文件与静态目录的哈希一致

## 6. 验收（只读方式）
- 内网 + 公网健康检查 200
- 核心页面/入口可访问（登录跳转属正常）
- 关键业务行为抽查（用只读账号或只读事务，避免写入生产）
- 日志近 N 分钟无异常堆栈
- 记录：现象 + 证据（状态码、日志行、数据快照）

## 7. 交付记录（写进 `docs/RELEASE.md` 与汇报）
版本 / 产物 sha / 备份路径 / 部署时间 / 验收结果 / 回滚方式 / **未完成或存疑项**

## 8. 回滚
- 旧产物 + 旧配置 + 数据备份 → 恢复版本号 → 重启 → 复验
- **回滚要演练过**：没演练过的回滚是假设。第一次发布后找机会真演练一次并记下步骤
- 数据迁移通常难以自动回退；涉及迁移时要单独说明回退方案

## 9. 禁止
覆盖生产配置 · 删除数据 · 跳过备份 · 带 `-v` 的 down · 未确认就改生产权限
