# 发布仪式 · exe / 可执行产物路线

> 用前先读项目里的 `docs/RELEASE.md`；本文件是骨架与检查点。
> **未验证提示**：此路线为通用骨架，尚未在真实项目中完整跑通，首次使用请按实际补齐步骤
> 并回写 `docs/RELEASE.md`。

## 0. 命名约定
- 版本 tag：`vX.Y.Z`；产物：`vX.Y.Z-<短hash>`（exe / 压缩包 / 安装包）
- **版本号要能自证**：程序内「关于 / 标题栏 / `--version`」显示的版本必须与产物名一致

## 1. 门禁
- 测试闸全绿（记录数量与耗时）
- 冒烟闸：**构建出的 exe 必须真实启动走一遍主流程**（不是只跑源码）

## 2. 提交与标记
- 只提交本轮相关文件 → 合主干 → 打 tag → 推送
- 版本号在代码/资源/清单里一次改全（避免产物名与显示版本不一致）

## 3. 干净构建
- 从 tag 导出构建（避免打进本地临时文件、测试数据、调试配置）
- 构建完成后抽查：
  - 产物内不含密钥、`.env`、本地数据库、测试样例
  - 无调试残留（调试符号/控制台输出按需要保留或剥离）
- 产物算校验和并记录

## 4. 备份（发布前，必须有）
- 现有可执行文件（重命名留档，例如 `app-prev.exe`）
- 配置（`config.ini` / `.env` / 注册表项 / 用户目录配置）
- 程序拥有的本地数据（若内容由程序管理）：导出或整目录拷贝，记录大小
- 记录：备份路径、旧版本号、旧产物 sha

## 5. 分发/替换
- 放到分发路径（共享目录 / 内网地址 / 安装包目录）
- 替换时**保留旧文件**，不要直接覆盖销毁
- 若程序常驻：先停 → 替换 → 再启动；说明是否需要重启系统或驱动

## 6. 验收
- **真实启动冒烟**：启动一次 → 走主流程 → 无报错弹窗 → 版本号显示正确
- 关键功能抽查（导入/导出/连接等该程序的核心能力）
- 若依赖外部资源（数据库、接口、共享盘）：确认连接成功
- 记录：启动结果 + 版本号截图/文本 + 核心功能结果

## 7. 交付记录（写进 `docs/RELEASE.md` 与汇报）
版本 / 产物 sha / 旧版留档路径 / 分发位置 / 验收结果 / 回滚方式 / **未完成或存疑项**

## 8. 回滚
- 旧 exe 改回原名 → 恢复配置与数据备份 → 重新启动 → 复验
- 若新版本改过数据结构（配置文件格式、数据库 schema）：说明旧版本能否读新数据，
  必要时给出降级脚本
- **回滚要演练过**

## 9. 禁止
未备份就替换 · 覆盖旧产物不留档 · 把测试数据/密钥打进产物 · 版本号与产物名不一致
