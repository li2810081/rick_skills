# 发布仪式 · 其他项目形态

适用于定时任务、Python/Node 脚本、静态前端、服务器服务、API/MCP、内部工具等不属于 Docker 或 exe 的项目。

## 1. 先判断是否需要发布仪式

- 只在本机运行、可随时撤回、没有外部写入：走核心必做，不强制打 tag 或备份生产。
- 会被他人使用、需要替换远程服务、定时运行或写入外部系统：按下面步骤执行。
- 涉及权限、密钥、生产数据、资金或不可逆变化：升级为 L2，先备份并准备回滚。

## 2. 发布前

- 从干净版本构建或导出，记录版本号、提交号和产物校验和。
- 核对配置与密钥只从指定位置读取，不把本地数据打进产物。
- 记录旧版本、旧配置、旧任务定义或旧静态资源的位置。
- 能做就先 dry-run；不能做就记录原因和预期变化。

## 3. 替换与验收

- 保留旧版本，执行替换、重启、重新加载或任务更新。
- 用真实入口验证：访问页面、运行主命令、触发一次任务或发送真实请求。
- 核对版本、健康状态、日志和关键只读结果；实际变化超出预期就停。

## 4. 回滚与记录

- 用旧产物、旧配置或旧任务定义恢复，再重新做健康检查。
- 记录版本、产物校验和、备份路径、验证证据、异常和未完成项。
- 高风险项目的回滚要演练过；未演练只能标记为假设。
